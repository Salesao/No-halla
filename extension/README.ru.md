# No-halla Gate

Самостоятельное расширение Chrome (Manifest V3), которое блокирует список
доменов, когда ваш **публичный IPv4-адрес** отсутствует в доверенном списке.
Это отдельный артефакт рядом с macOS-приложением No-halla: приложение не
требуется, расширение его не меняет и не читает его состояние (и наоборот).

- Минимальный Chrome: **121**
- Обычный JavaScript (ES-модули); без сборки и npm-зависимостей
- Интерфейс EN/RU, токены светлой / тёмной / контрастной темы
- Весь внешний трафик ограничен настроенным HTTPS-эндпоинтом проверки IP

## Установка (unpacked)

1. Откройте `chrome://extensions` и включите **Режим разработчика**.
2. Нажмите **Загрузить распакованное расширение** и выберите каталог
   `extension/`.
3. Откройте настройки расширения (иконка пазла → No-halla Gate → Настройки).
4. Нажмите **Добавить текущий IP**, чтобы доверять текущему адресу.
5. Добавьте домены, которые нужно защищать. Chrome спросит доступ к каждому
   домену; разрешите. Отказ означает, что домен не добавлен.

Popup на панели показывает тот же список доменов и умеет добавлять и удалять
их. При добавлении доступ Chrome запрашивается прямо из popup. Если Chrome не
показывает запрос из popup (известное ограничение) или вы его отклонили, домен
не добавляется и появляется короткая ошибка; добавьте его через настройки.
Если popup закрылся, пока запрос виден, выдача доступа всё равно
подхватывается и домен сохраняется. В popup также есть
кнопка **Добавить текущий IP** и кнопка **Добавить текущий сайт**, которая
добавляет домен активной вкладки.

Расширение не опубликовано в Chrome Web Store.

## Как это работает

**Сигнал доверия.** `fetch` к настроенному эндпоинту (по умолчанию
`https://ipinfo.io/ip`) возвращает публичный IPv4 обычным текстом. Адрес
строго разбирается как IPv4 и сверяется с доверенным списком (`a.b.c.d` или
CIDR `/0`–`/32`). Результат:

| Вердикт | Значение | Ворота |
| --- | --- | --- |
| `trusted` | адрес совпал с доверенным списком | открыты |
| `untrusted` | корректный IPv4, но не в списке | закрыты |
| `unknown` | сеть/таймаут/не-200/HTTP-редирект/IPv6/невалидное тело/пустой доверенный список | закрыты |

`unknown` никогда не считается доверенным. Запрос использует
`cache: "no-store"`, `credentials: "omit"`, `redirect: "error"` и обрыв через
2,5 с.

**Когда выполняется проверка.**

- При запросе к домену из списка (`chrome.webRequest` наблюдает только за
  доменами списка; не чаще одной проверки в 3 с, параллельные запросы
  дедуплицируются).
- При старте браузера и установке/обновлении расширения.
- По кнопке **Проверить сейчас** и на странице-заглушке.
- Опционально — в фоне. **Фоновая проверка по умолчанию выключена.** Если
  включить, alarm работает с выбранным интервалом. Chrome может поднять
  слишком короткий период до своего минимума 30 с. Выключено
  по решению владельца: проверка идёт при открытии домена из списка.

**Блокировка.** Правила Declarative Net Request строятся на каждый домен:

- навигация и фреймы → редирект на локальную страницу-заглушку;
- все остальные типы ресурсов → блокировка (`ERR_BLOCKED_BY_CLIENT`).

`requestDomains` покрывает домен и его поддомены. Когда ворота закрываются
(или добавляется заблокированный домен), уже открытые вкладки доменов из
списка один раз перезагружаются, чтобы SPA не продолжал работать из памяти;
перезагрузка попадает под redirect и показывает страницу-заглушку. После
каждого обновления правила проверяются через `getDynamicRules()`. Если обновление отклонено или
проверка не совпала, расширение сообщает `unknown`/degraded и никогда не
считает соединение доверенным. Правила переживают перезапуск браузера.

**Fail-closed старт.** При каждом холодном старте service worker состояние
правил — `unknown`, даже если сохранённый вердикт `trusted`. Правила остаются
(или применяются) до свежей проверки, доказывающей доверие, и проверенного
удаления. Повреждённый конфиг никогда не снимает правила.

**Мастер-выключатель** снимает все правила. Включение запускает проверку.
**Пустой доверенный список** означает, что доверенного нет: домены из списка
блокируются с причиной «список пуст», пока вы не добавите адрес.

## Разрешения

| Разрешение | Зачем |
| --- | --- |
| `declarativeNetRequest` | динамические правила block/redirect |
| `webRequest` | наблюдение только за доменами списка (без блокировки и тел запросов) |
| `storage` | конфиг и состояние UI в `chrome.storage.local` |
| `alarms` | опциональная фоновая проверка |
| `activeTab` | прочитать URL активной вкладки по клику на иконку — для **Добавить текущий сайт** |

Никаких `notifications`, `webRequestBlocking`, `<all_urls>` в
`host_permissions`. Доступ к сайтам запрашивается по домену при добавлении,
плюс origin эндпоинта проверки IP. `optional_host_permissions` объявлены
шаблоном, чтобы такие запросы были возможны; при установке выдан только origin
эндпоинта по умолчанию (`https://ipinfo.io/*`), доступ к сайтам не выдан.
`web_accessible_resources` совпадает со всеми сайтами только чтобы страницу-
заглушку можно было открыть после редиректа с любого домена списка; сетевого
доступа это не даёт, используется `use_dynamic_url: true`.

## Честные ограничения

1. **Первый запрос может утечь.** MV3 не видит IP соединения до его начала.
   После смены публичного IP первый запрос к домену из списка может ещё дойти
   до сайта; запущенная им проверка блокирует остальные. «Ни одного запроса»
   браузерное расширение обеспечить не может.
2. **Фоновая проверка по умолчанию выключена.** Если IP сменился, пока вы не
   открываете домены списка, это не обнаружится до следующего запроса к ним,
   старта браузера, открытия popup или «Проверить сейчас».
3. **Ответы service worker и CacheStorage** не покрываются DNR. Уже
   закэшированное PWA может работать из своего кэша. Навигация и новые запросы
   покрыты, включая обычный HTTP-кэш.
4. **Уже полученные ответы** не отозвать.
5. **Сбой эндпоинта блокирует.** Если эндпоинт недоступен, ограничивает
   частоту или возвращает не обычный IPv4, вердикт `unknown`, ворота закрыты.
   Смените эндпоинт или добавьте текущий IP.
6. **Другие расширения могут перебить блокировку.** Правило `allow`
   приоритетнее `block`, а правила позже установленного расширения применяются
   раньше. Вне unpacked-разработки это не детектируется (`getMatchedRules`).
7. **Service worker засыпает.** MV3 останавливает его после простоя. Запросы к
   доменам списка и alarm будят его; во сне проверка невозможна.
8. **Инкогнито.** Приватные окна защищены, только если расширение разрешено в
   инкогнито. Chrome не даёт включить это из расширения; включите вручную:
   `chrome://extensions` → No-halla Gate → Details → Allow in incognito.
   Split-инкогнито — отдельный экземпляр.
9. **Dual-stack и TLS-перехват.** Эндпоинт может ответить по IPv6, а трафик к
   сайтам идти по IPv4 (другой выход), либо корпоративный прокси с доверенным
   корневым сертификатом подменит ответ. Оба случая дают ложный `trusted`. У
   macOS-приложения тот же предел; по решению владельца используется один
   эндпоинт.
10. **Отключение расширения** (пользователем или политикой) мгновенно удаляет
    все правила. Вне Chrome защиты нет.

## Файлы

```
manifest.json          манифест MV3
src/cidr.js            строгий разбор IPv4/CIDR и сопоставление
src/config.js          схема storage, валидация, состояние
src/trust.js           запрос эндпоинта -> вердикт
src/rules.js           построение правил DNR, сверка, проверка
src/sw.js              оркестрация, триггеры, сообщения, alarm, разрешения
src/i18n.js            загрузка локалей, t(), локализация документа
ui/tokens.css          дизайн-токены (light/dark/contrast)
ui/popup.*             popup статуса
ui/options.*           настройки
ui/blocked.*           страница-заглушка (только ресурсы пакета)
_locales/{en,ru}/      генерируются из design/copy.json (ключи gate.*)
icons/                 PNG 16/32/48/128
README.md, README.ru.md
```

Копи интерфейса генерируются из единственного источника репозитория
`design/copy.json`:

```sh
python3 scripts/gen-extension-strings.py
```

Не редактируйте `_locales/*/messages.json` вручную. String Catalog
Swift-приложения и `scripts/gen-strings.py` в этот артефакт не входят.

Тесты для проекта не запрошены (решение владельца). Проверка — статическая и
ручная матрица ниже.

Статические проверки (из корня репозитория):

```sh
for f in extension/src/*.js extension/ui/*.js; do node --check "$f"; done
python3 -m json.tool extension/manifest.json
python3 -m json.tool extension/_locales/en/messages.json
python3 -m json.tool extension/_locales/ru/messages.json
python3 -m json.tool design/copy.json
python3 scripts/gen-extension-strings.py
xcodegen generate && ./scripts/build.sh   # сборка macOS-приложения должна остаться зелёной
```

Ручная матрица (Chrome, unpacked-расширение; результаты фиксируются на релиз).
Автоматический smoke-прогон 2026-11-21 использовал временный CDP-скрипт (не
входит в репозиторий), Chrome for Testing 156, локальный HTTPS-мок IP и
тестовую копию манифеста со статически выданными доступами к двум хостам
`example.com` и `127.0.0.1`; **51/51 проверок прошли**. Скрипт работал с
настоящим service worker, правилами, страницей-заглушкой, popup и настройками,
включая смену конфига во время медленной проверки и повреждённый конфиг.
Интерактивные запросы доступа и split-инкогнито
остаются ручными.

| # | Сценарий | Ожидание | Статус |

| 5 | Мастер off / on | все домены открываются / снова блокируются | PASS (smoke) |

| 14 | Повреждённый сохранённый конфиг | настройки заблокированы, правила не тронуты, Save отклонён; починка + перезагрузка разблокирует | PASS (smoke) |

Чтобы проверить смену IP без смены сети, укажите эндпоинт на HTTPS-мок,
возвращающий фиксированный недоверенный адрес (например, локальный сервер с
сертификатом, которому доверяет Chrome), и нажмите **Проверить сейчас**.

## Приватность

Конфиг и состояние хранятся в `chrome.storage.local`. Нет телеметрии,
аккаунтов и авто-обновления. Единственный внешний запрос — настроенный
HTTPS-эндпоинт проверки IP. Диагностика никуда не отправляется.

# No-halla Gate для Firefox

Самостоятельное расширение Firefox (Manifest V3), которое блокирует список
доменов, когда ваш **публичный IPv4-адрес** отсутствует в доверенном списке.
Это отдельный артефакт рядом с macOS-приложением No-halla: приложение не
требуется, расширение его не меняет и не читает его состояние (и наоборот).

Это порт Chrome-артефакта из `extension/` на Firefox. Поведение, схема
хранилища, политика fail-closed и интерфейс совпадают; платформенный слой
использует event page Firefox, promise-API `browser.*` и правила DNR Firefox.

- Минимальный Firefox: **140** на десктопе (MV3 event page с фоновым
  ES-модулем, `optional_host_permissions` и встроенное объявление сбора
  данных); **142** на Firefox for Android, где это объявление поддерживается
- Обычный JavaScript (ES-модули); без сборки и npm-зависимостей
- Интерфейс EN/RU, токены светлой / тёмной / контрастной темы
- Весь внешний трафик ограничен настроенными HTTPS-эндпоинтами проверки IP
  (основным и добавленными резервными)

## Установка

### Временная (для разработки)

1. Откройте `about:debugging#/runtime/this-firefox`.
2. Нажмите **Load Temporary Add-on…** и выберите
   `extension-firefox/manifest.json` (или любой файл в каталоге).
3. Расширение остаётся загруженным до перезапуска Firefox. **Reload**
   перечитывает манифест и разрешения.

### Подписанная (постоянная)

Для постоянной установки вне Developer Edition / Nightly с отключённой
проверкой подписи нужна подпись AMO. Manifest V3 требует фиксированный ID
расширения в `browser_specific_settings.gecko.id` (`gate@nohalla.dev`).

- **Listed (публичная страница AMO):** загрузите zip каталога
  `extension-firefox/` на <https://addons.mozilla.org/developers/> или
  выполните `web-ext sign --api-key=… --api-secret=… --channel=listed`.
  Listed-версии обновляются автоматически через AMO.
- **Unlisted (самостоятельное распространение):** тот же процесс с
  `--channel=unlisted`. Для обновления самостоятельно распространяемого XPI
  нужен `update_url` либо следующую версию нужно отправить в AMO на подпись.
- AMO принимает обычный `.zip`; `web-ext` не обязателен. Если используете его,
  собирайте архив из каталога `extension-firefox/`, чтобы `manifest.json`
  лежал в корне zip.

Расширение не публикуется в Chrome Web Store и не имеет Chrome-сборки.

## Первый запуск

1. Откройте настройки расширения (иконка на панели → **Settings**, либо
   `about:addons` → No-halla Gate → Preferences).
2. Нажмите **Add current IP**, чтобы доверять текущему адресу.
3. Добавьте домены, которые нужно защищать. Firefox спросит доступ к каждому
   домену; разрешите. Отказ означает, что домен не добавлен, и показывает
   короткую ошибку.

Popup на панели показывает тот же список доменов и умеет добавлять и удалять
их. При добавлении доступ Firefox запрашивается прямо из popup. Если Firefox
закроет popup, пока запрос виден, выдача доступа всё равно подхватывается
фоновой страницей, и домен сохраняется. В popup также есть кнопка
**Add current IP** и кнопка **Add current site**, которая добавляет домен
активной вкладки.

## Как это работает

**Сигнал доверия.** `fetch` к настроенному эндпоинту (по умолчанию
`https://ipinfo.io/ip`) возвращает публичный IPv4 обычным текстом. Адрес
строго разбирается как IPv4 и сверяется с доверенным списком (`a.b.c.d` или
CIDR `/0`–`/32`). Результат:

| Вердикт | Значение | Ворота |
| --- | --- | --- |
| `trusted` | адрес совпал с доверенным списком | открыты |
| `untrusted` | корректный IPv4, но не в списке | закрыты |
| `unknown` | сеть/таймаут/не-200/HTTP-редирект/IPv6/невалидное тело/пустой доверенный список | закрыты |

`unknown` никогда не считается доверенным. Запрос использует
`cache: "no-store"`, `credentials: "omit"`, `redirect: "error"` и обрыв через
2,5 с. Транспортная ошибка (`TypeError`, например периодический
`ERR_CONNECTION_CLOSED` в Firefox) повторяется один раз в пределах 4 с;
таймаут, ответ не-2xx, редирект и неразбираемое тело не повторяются.

**Проверка из вкладки.** Если вкладка домена из списка уже открыта, та же
HTTPS-проверка выполняется внутри неё (`browser.scripting.executeScript`,
изолированный мир), а не на фоновой странице, и использует тот же сетевой
путь, что и страница. Этот вердикт главный; фоновая проверка выполняется,
когда открытой вкладки списка нет, вкладка недоступна или эндпоинт не
разрешает cross-origin чтение. Неудачная проверка из вкладки никогда не
открывает ворота.

**Резервные эндпоинты.** Основной эндпоинт можно выбрать из списка пресетов
или ввести свой (только HTTPS; тело — обычный IPv4). До восьми дополнительных
эндпоинтов добавляются из списка. Проверка начинается со следующего эндпоинта
в ротации и пробует до четырёх по очереди: первый валидный IPv4 (доверенный
или нет) — окончательный; сетевая ошибка, не-2xx, редирект или неразбираемое
тело передают ход следующему; если все попытки неудачны, вердикт `unknown` и
ворота закрыты. Валидный недоверенный адрес не перепроверяется на других
эндпоинтах. Проверка из вкладки пропускает известные пресеты без
`Access-Control-Allow-Origin` (они используются только фоновой проверкой);
пользовательский URL пробуется и при CORS-отказе передаёт ход следующему.
HTTP-сервисы вроде `ip-api.com` не предлагаются: открытый ответ можно
подменить в пути. Каждый включённый эндпоинт видит ваш IP. Пресеты и их CORS
лежат в `src/endpoints.js`.

**Когда выполняется проверка.**

- При переходе на домен из списка (`browser.webRequest` наблюдает только
  переходы main_frame/sub_frame для доменов списка; свежий вердикт
  переиспользуется 30 с, параллельные запросы дедуплицируются).
- При старте браузера и установке/обновлении расширения.
- По кнопке **Check now** и на странице-заглушке.
- Пока активная вкладка — видимый домен из списка, content script просит
  проверку примерно каждые 2 секунды, чтобы смена IP замечалась без навигации.
  Скрипт регистрируется только для доменов списка с выданным доступом и только
  пока включена фоновая проверка; тики из любой другой вкладки игнорируются.
- Опционально — в фоне. **Фоновая проверка по умолчанию выключена.** Если
  включить, alarm с периодом 30 с проверяет только пока активная вкладка —
  домен из списка (даже если окно свёрнуто или перекрыто). Переключение на
  другую вкладку или домен не делает автоматических запросов. Firefox
  использует этот интервал как есть, но всё равно может задержать alarm, если
  браузер занят или спит, а alarms не переживают перезапуск браузера — фоновая
  страница создаёт alarm заново при каждом холодном старте. Выключено по
  решению владельца: проверка идёт при открытии домена из списка.

**Блокировка.** Правила Declarative Net Request строятся на каждый домен:

- навигация и фреймы → редирект на локальную страницу-заглушку;
- все остальные типы ресурсов → блокировка.

`requestDomains` покрывает домен и его поддомены. Цель редиректа — абсолютный
URL `moz-extension://…/ui/blocked.html?domain=…`: у Firefox нет query-строк в
`redirect.extensionPath`, а параметр сохраняет имя домена, даже если Firefox
перенаправляет запрос раньше, чем `webRequest` увидит навигацию. Когда ворота
закрываются (или добавляется заблокированный домен), уже открытые вкладки
доменов из списка один раз перезагружаются, чтобы SPA не продолжал работать
из памяти; перезагрузка попадает под redirect и показывает страницу-заглушку.
После каждого обновления правила проверяются через `getDynamicRules()`. Если
обновление отклонено или проверка не совпала, расширение сообщает
`unknown`/degraded и никогда не считает соединение доверенным. Правила
переживают перезапуск браузера и обновление расширения. Firefox разрешает
5000 динамических правил; лимит в 500 доменов даёт максимум 1000.

**Fail-closed старт.** При каждом старте фоновой страницы состояние правил —
`unknown`, даже если сохранённый вердикт `trusted`. Правила остаются (или
применяются) до свежей проверки, доказывающей доверие, и проверенного
удаления. Повреждённый конфиг никогда не снимает правила.

**Мастер-выключатель** снимает все правила. Включение запускает проверку.
**Пустой доверенный список** означает, что доверенного нет: домены из списка
блокируются с причиной «список пуст», пока вы не добавите адрес.

## Разрешения

| Разрешение | Зачем |
| --- | --- |
| `declarativeNetRequest` | динамические правила block/redirect; block продолжает работать, даже если позже отозвать доступ к сайту |
| `webRequest` | наблюдение только за доменами списка (без блокировки и тел запросов) |
| `storage` | конфиг и состояние UI в `browser.storage.local` |
| `alarms` | опциональная фоновая проверка |
| `activeTab` | прочитать URL активной вкладки по клику на иконку — для **Add current site** |
| `scripting` | выполнить проверку IP внутри уже открытой вкладки домена из списка (изолированный мир) и зарегистрировать heartbeat видимой вкладки |

Никаких `notifications`, `webRequestBlocking`, `<all_urls>` в
`host_permissions`. Доступ к сайтам запрашивается по домену при добавлении,
плюс origin каждого эндпоинта проверки IP (в манифесте выдан только origin по
умолчанию `https://ipinfo.io/*`; при добавлении резервного запрашивается его
хост). `optional_host_permissions` объявлены
шаблоном, чтобы такие запросы были возможны; при установке выдан только origin
эндпоинта по умолчанию (`https://ipinfo.io/*`), доступ к сайтам не выдан.

Используется `declarativeNetRequest`, а не Firefox-специфичный
`declarativeNetRequestWithHostAccess`. Для редиректа фрейма Firefox в любом
случае требует доступ к хосту, но только обычное разрешение позволяет
правилам `block` работать без него. Если позже отозвать доступ к сайту в
`about:addons`, наблюдение и редирект для этого домена прекращаются, но
блокировка сабресурсов продолжает работать, а не открывает сайт. Для
редиректа фреймов всё ещё нужен доступ к домену, который расширение
запрашивает при добавлении. Firefox показывает `declarativeNetRequest` в
запросе при установке; созданные правила совпадают только с добавленными
доменами, а не со всеми сайтами.

`web_accessible_resources` совпадает со всеми сайтами только чтобы страницу-
заглушку можно было открыть после редиректа с любого домена списка; сетевого
доступа это не даёт. У Firefox нет `use_dynamic_url`, поэтому URL
`moz-extension://` стабилен на всё время жизни профиля.

## Объявление сбора данных Firefox

Firefox 140+ показывает встроенное согласие на сбор данных из
`browser_specific_settings.gecko.data_collection_permissions`. Манифест
объявляет `required: ["none"]`: расширение не отправляет никаких данных ни
автору, ни третьим лицам; телеметрии, аккаунтов, аналитики и отчётов о
падениях нет. Firefox for Android поддерживает это объявление только с 142,
поэтому `browser_specific_settings.gecko_android.strict_min_version` равен
`142.0`, а десктопный минимум остаётся `140.0`; без этого разделения AMO
предупреждает, что Android-минимум старше объявления.

Каждый настроенный эндпоинт проверки IP (основной и резервные) неизбежно видит
исходный IP своего HTTPS-запроса, как и любой запрос к этому серверу. Полученный
адрес сверяется с доверенным списком и хранится в `browser.storage.local`
внутри браузера; больше никуда он не отправляется. Основной эндпоинт по
умолчанию — `https://ipinfo.io/ip`; его смена или добавление резервных меняет
третьи стороны, которые видят запрос.
Это описано в разделе «Приватность» и должно быть повторено в примечании к
отправке в AMO.

## Честные ограничения

1. **Первый запрос может утечь.** Расширение не видит IP соединения до его
   начала. После смены публичного IP первый запрос к домену из списка может
   ещё дойти до сайта; запущенная им проверка блокирует остальные. «Ни одного
   запроса» браузерное расширение обеспечить не может.
2. **Фоновая проверка по умолчанию выключена.** Если IP сменился, пока вы не
   открываете домены списка, это не обнаружится до следующего запроса к ним,
   старта браузера, открытия popup или «Check now».
3. **Event page Firefox засыпает.** Firefox останавливает фоновую страницу
   после простоя. Запросы к доменам списка, alarm и сообщения UI будят её; во
   сне проверка невозможна.
4. **Ответы event page и CacheStorage** не покрываются DNR. Уже закэшированное
   PWA может работать из своего кэша. Навигация и новые запросы покрыты,
   включая обычный HTTP-кэш.
5. **Уже полученные ответы** не отозвать.
6. **Сбой эндпоинта блокирует.** Если эндпоинт недоступен, ограничивает
   частоту или возвращает не обычный IPv4, вердикт `unknown`, ворота закрыты.
   Смените эндпоинт или добавьте текущий IP.
7. **Другие расширения могут перебить блокировку.** Правило `allow`
   приоритетнее `block`, а конфликты правил между расширениями Firefox
   разрешает по своим правилам приоритета. Расширение не может это
   обнаружить.
8. **Приватные окна.** Приватные окна защищены, только если расширение
   разрешено в них. Включите: `about:addons` → No-halla Gate → **Details** →
   **Run in Private Windows** → **Allow**. API включить это из расширения нет.
   Приватные окна Firefox используют тот же экземпляр расширения.
9. **Dual-stack и TLS-перехват.** Эндпоинт может ответить по IPv6, а трафик к
   сайтам идти по IPv4 (другой выход), либо корпоративный прокси с доверенным
   корневым сертификатом подменит ответ. Оба случая дают ложный `trusted`. У
   macOS-приложения тот же предел; по решению владельца используется один
   эндпоинт.
10. **Проверке из вкладки нужны открытая вкладка списка и эндпоинт с CORS.**
    Если открытой вкладки списка нет (например, все страницы списка уже
    перенаправлены на заглушку), используется фоновый путь. Firefox считает
    запрос из content script в MV3 cross-origin, поэтому пользовательский
    эндпоинт должен разрешить его через `Access-Control-Allow-Origin`;
    `ipinfo.io` разрешает. Запрос не несёт cookies и credentials, а `Referer`
    расширение подавляет. Если ошибочны оба пути, ворота остаются закрытыми.
11. **Heartbeat работает только пока активная вкладка — видимый домен из
    списка.** Переключение на другую вкладку или домен полностью останавливает
    автоматические проверки; alarm раз в 30 с тоже требует активную вкладку
    домена из списка (он покрывает свёрнутое или перекрытое окно). У вкладки,
    уже перешедшей на заглушку, heartbeat нет — восстановление оттуда ручное.
    Активная видимая вкладка списка даёт около тридцати проверок в минуту;
    ограничения эндпоинта и существующий backoff по-прежнему действуют.
12. **Каждый резервный эндпоинт — ещё один источник доверия.** Каждый
    включённый эндпоинт видит ваш IP; сломанный эндпоинт может добавить до 2 с
    до следующей попытки, и все хосты включённых эндпоинтов должны быть
    разрешены. Если все попытки неудачны, вердикт `unknown` и ворота закрыты.
    Проверка из вкладки пропускает эндпоинты без CORS — они используются
    только фоновой проверкой.
13. **Отключение расширения** (пользователем или политикой) мгновенно удаляет
    все правила. Вне Firefox защиты нет.

## Локализация

`design/copy.json` — единый общий источник копи репозитория, и этот артефакт
его не меняет. `scripts/gen-firefox-strings.py` читает его ключи `gate.*`,
применяет `extension-firefox/localization-overrides.json` (формулировки
запросов Firefox, поведение alarm, примечание об утечке) и записывает
`extension-firefox/_locales/{en,ru}/messages.json`. В файле переопределений
только браузерно-специфичные варианты; все остальные строки берутся из общего
источника. Генератор падает на неизвестном ключе переопределения, пустом или
отсутствующем значении EN/RU, именованном placeholder или дубликате имени
сообщения.

```sh
python3 scripts/gen-firefox-strings.py
```

Не редактируйте `_locales/*/messages.json` вручную.
`scripts/gen-extension-strings.py` (Chrome-артефакт) и String Catalog
Swift-приложения отдельны и не затрагиваются.

## Проверка

Тесты для проекта не запрошены (решение владельца). Проверка — статическая и
ручная матрица.

Чтобы проверить смену IP без смены сети, укажите эндпоинт на HTTPS-мок,
возвращающий фиксированный недоверенный адрес (например, локальный сервер с
сертификатом, которому доверяет Firefox), и нажмите **Check now**.

## Приватность

Конфиг и состояние хранятся в `browser.storage.local` внутри профиля Firefox.
Нет телеметрии, аккаунтов, аналитики и авто-обновления. Единственные внешние
запросы — настроенные HTTPS-эндпоинты проверки IP: основной и добавленные
резервные. Каждый включённый эндпоинт видит ваш IP. Проверка из вкладки идёт в
открытой вкладке списка, не несёт cookies и credentials и подавляет `Referer`;
расширение хранит полученный адрес локально и больше никуда его не отправляет.
Heartbeat видимой вкладки лишь запрашивает ту же проверку и не отправляет
собственных данных. Эндпоинт видит исходный IP запроса, как и для любого
HTTPS-клиента.

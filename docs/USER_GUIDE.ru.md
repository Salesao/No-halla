# Руководство по No-halla

[К описанию приложения](../README.ru.md) · [English](USER_GUIDE.md) · **Русский**

## Режимы защиты

| Режим | Когда выбрать | Как работает |
| --- | --- | --- |
| **VPN-туннель** | VPN может выдавать новый адрес при каждом подключении | No-halla следит за активным туннелем на Mac. При раздельной маршрутизации часть трафика может идти в обход работающего туннеля. |
| **Белый список IP** | Для работы нужен определённый внешний IPv4-адрес или диапазон CIDR | Каждый настроенный HTTPS-сервис сообщает, с какого IP пришёл запрос. Все полученные адреса должны входить в доверенный список. Пока список пуст, приложение предлагает завершить настройку. |

No-halla проверяет соединение при смене сети, после выхода из сна и периодически. По умолчанию интервал между проверками составляет **30 секунд**, задержка перед заморозкой — **1 секунду**, а после ручного возобновления приложениям даётся **5 минут**.

В режиме проверки по IP внешний адрес по умолчанию сообщает `https://ipinfo.io/ip`. Свой HTTPS-сервис можно добавить в разделе **Настройки → Дополнительно**. Он должен возвращать IPv4-адрес обычным текстом или в JSON, например `{"ip":"203.0.113.5"}`. Проверка внешнего адреса охватывает только IPv4.

Если ни один сервис не ответил, запущенные приложения по умолчанию продолжают работать. Чтобы в этом случае ставить их на паузу после отсчёта, включите **«Замораживать, если IP не удалось проверить»** в настройках защиты. Уже замороженные приложения дождутся доверенного соединения или ручного возобновления.

Во время отсчёта кнопка **«Отмена»** запускает повторную проверку. Замороженные приложения возобновляют работу автоматически, когда соединение снова становится доверенным. Чтобы временно запустить их на недоверенном соединении, выберите **«Возобновить все»** в уведомлении о заморозке. Нажмите **«Возобновить защиту»**, чтобы закончить этот период раньше. Выключение переключателя **«Защита»** возобновляет приложения до следующего включения защиты. Автозапуск, уведомления и язык интерфейса можно изменить в разделе **Настройки → Основные**.

**Сон и пробуждение.** No-halla не замораживает приложения, пока Mac спит, и не возобновляет их во сне по устаревшему результату проверки — замороженные приложения остаются замороженными до первой проверки после пробуждения. После пробуждения сразу выполняется проверка; отсчёт, начавшийся до сна, возобновляется только если новая проверка снова признаёт соединение недоверенным. В режиме **VPN-туннель** после пробуждения даётся несколько секунд на переподключение VPN, и только потом отсутствие туннеля может привести к заморозке. Пауза на 15 минут или 1 час считается по обычным часам: время сна засчитывается, и пауза, истёкшая во сне, заканчивается сразу после пробуждения. Пауза **до перезапуска** не меняется. Если уведомление о пробуждении вдруг потеряется, No-halla восстановится при следующем включении экрана, разблокировке сеанса или любом вашем действии в приложении; жёсткий предел в 12 часов принудительно восстанавливает защиту и записывается в журнал как ошибка.

## Терминалы с агентами

При первом запуске No-halla на шаге выбора приложений добавьте каждое приложение, в котором запускаете агента, и выберите для него **«Терминалы агентов»**. Например, можно защитить одновременно Codex в Orca и Claude Code в стандартном «Терминале» macOS. Чтобы «Терминал» появился в списке запущенных приложений, откройте его до перехода к этому шагу.

No-halla находит агента, привязанного к терминалу, и приостанавливает весь его сеанс — оболочку и дочерние процессы, включая команды, которые уже запустил агент. Окно приложения остаётся отзывчивым. В других вкладках без агентов можно продолжать работу, в том числе по SSH. Пока действует заморозка, No-halla каждые пять секунд ищет новые сеансы с агентами.

Поддерживаются Claude Code, Codex, Antigravity, Gemini, Grok Build, GitHub Copilot, Cursor, Factory Droid, Amp, Kiro, Aider, OpenCode, Crush, Goose и OpenHands. Фоновые агенты без терминала и сеансы внутри `tmux` или `screen` этим способом не обнаруживаются. [Список агентов в исходном коде](../NoHalla/Core/Process/AgentDetector.swift)

## Восстановление и конфиденциальность

Перед отправкой `SIGSTOP` No-halla сохраняет идентификатор процесса (PID) и время его запуска. Она проверяет владельца и принадлежность процесса пакету приложения, а для терминалов с агентами — связь с приложением через дерево процессов. Из заморозки исключены системные процессы, сама No-halla и её сторожевой процесс.

При штатном выходе и сигналах `SIGTERM` или `SIGINT` No-halla отправляет замороженным процессам `SIGCONT`, чтобы они продолжили работу. После сбоя этим занимается встроенный сторожевой процесс. При следующем запуске No-halla также проверяет оставшиеся записи. Если между сохранением записи и заморозкой тот же процесс остановил отладчик, восстановление может снять и эту паузу.

Настройки и состояние для восстановления записываются атомарно в `~/Library/Application Support/NoHalla/`. В No-halla нет учётных записей и телеметрии. Для определения публичного IP приложение обращается к настроенным HTTPS-сервисам, в том числе на экране выбора доверенного адреса при первом запуске. При обычном уровне журналирования IP-адреса маскируются. **Настройки → Дополнительно → Экспорт диагностики…** сохраняет локальный архив с конфигурацией, состоянием и доступными недавними записями журнала. В архив могут попасть доверенные адреса.

## Решение проблем

| Что происходит | Что проверить |
| --- | --- |
| Приложения замораживаются при работающем VPN | В режиме проверки по IP проверьте маршрут до каждого из настроенных сервисов. При раздельной маршрутизации один из них может видеть ваш домашний IP. Кнопка «Добавить текущий IP» добавляет все адреса, полученные при последней проверке. |
| После сбоя приложение осталось на паузе | Запустите No-halla повторно для восстановления. Если это не помогло, найдите PID остановленного процесса в «Мониторинге системы» и выполните для него `kill -CONT <pid>`, подставив найденный номер. |
| При заморозке окно скрывается вместо сворачивания в Dock | Разрешите No-halla управлять окнами в **Системные настройки → Конфиденциальность и безопасность → Универсальный доступ**. После локальной пересборки macOS может снова запросить это разрешение. |
| Не включается запуск при входе | Посмотрите сообщение рядом с переключателем в разделе «Основные». macOS может отклонить регистрацию приложения с подписью ad hoc. |
| На macOS 13 клавиша Esc оставляет панель открытой | Нажмите значок No-halla в строке меню ещё раз. |

## Сборка из исходников

На Mac с Xcode 15 или новее установите XcodeGen и выполните команды из корня репозитория.

```bash
brew install xcodegen
./scripts/build.sh
./scripts/run.sh
```

Скрипт генерирует проект Xcode из `project.yml` и собирает схему **NoHalla** для arm64 и x86_64. Приложение появится по пути `build/Build/Products/Release/No-halla.app`. Оно подписано локально (ad hoc) с включённым Hardened Runtime. Встроенный сторожевой процесс находится в `Contents/MacOS/NoHallaWatchdog`.

Для создания DMG, ZIP и файла контрольных сумм в `dist/` запустите `./scripts/package.sh` в графическом сеансе с разрешением на управление Finder. Чтобы пройти первоначальную настройку заново, сначала посмотрите, какие данные будут удалены, командой `./scripts/reset-app.py --dry-run`. Без этого флага скрипт очистит пользовательские данные No-halla и откроет приложение заново.

## Удаление

1. В разделе «Основные» выключите **«Запускать при входе»**.
2. Выйдите из No-halla, чтобы замороженные приложения продолжили работу. Затем удалите **No-halla.app** из папки «Программы».
3. Если настройки и файлы восстановления больше не нужны, удалите `~/Library/Application Support/NoHalla/`.
